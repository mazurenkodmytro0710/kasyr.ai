# 🎨 Design Prompt — FOP BUGALTER / Kasyr.ai

## Контекст проекту

Ти — провідний product designer, що спеціалізується на B2B SaaS і FinTech. Ми разом розробляємо **AI-бухгалтерію для українських ФОП** — продукт, який автоматично підключається до банків (Monobank, Приват24, Wise, Payoneer), веде Книгу обліку доходів і допомагає подавати квартальні податкові звіти без бухгалтера.

**Робоча назва:** Kasyr.ai (або FopAgent / FOPus — ще вибираємо)  
**Позиціонування:** «Stripe для ФОП» — сучасний, мінімалістичний, довірливий  
**Цільова аудиторія:** IT-фрілансери, дизайнери, digital-підприємці, ФОП 3 групи, 25–40 років, живуть у Notion, Figma, Linear — і ненавидять iFin та BAS

---

## Наш головний диференціатор у дизайні

Всі конкуренти (Taxer, iFin, BAS, Smartfin) мають **UI з 2012–2015 року**. Наша аудиторія — digital natives, які звикли до Stripe, Linear, Notion, Vercel. Вони готові платити більше за продукт, який виглядає як сучасний tech-продукт, а не урядовий портал. Це — наша головна дизайн-перевага.

## Завдання

Ми хочемо спроектувати **повний дизайн застосунку** — від брендингу до кожного екрану. Розбий роботу на такі блоки:

---

### Блок 1: Design System & Brand Identity

Розроби повноцінну дизайн-систему з нуля:

**Бренд-директиви:**
- Tone of voice: впевнений, дружній, без бюрократії. Як розумний друг-бухгалтер, а не держорган
- Не банк і не держслужба — tech-продукт для підприємців
- Викликає довіру з фінансами, але не виглядає нудно

**Кольорова палітра:**
- Запропонуй primary color (не синій банківський — щось сучасне: indigo, teal, slate або violet)
- Нейтральні (gray scale) для фону і тексту
- Semantic colors: success (зелений для доходу), warning (дедлайн наближається), danger (прострочено, штраф)
- Dark mode як обов'язковий варіант

**Типографіка:**
- Google Font або system font stack
- Hierarchy: Display / H1–H3 / Body / Caption / Label
- Числа — tabular figures (для таблиць і сум)

**Компонентна бібліотека (Figma):**
- Buttons (primary, secondary, ghost, destructive, loading state)
- Inputs (text, number, date, search, з validation states)
- Cards (summary card, transaction card, deadline card)
- Badges (статус транзакції: дохід / повернення / переказ / комісія)
- Data table (з сортуванням, pagination, bulk actions)
- Modals & Sheets (bottom sheet для мобайл)
- Toast notifications
- Empty states (з ілюстрацією і CTA)
- Skeleton loaders
- Navigation (sidebar для desktop, bottom nav для мобайл)

### Блок 2: Онбординг (перший запуск)

Принцип «3 кроки і ти вже всередині». Ціль — підключений банк до того, як користувач почне думати.

**Екрани онбордингу:**
1. **Welcome screen** — value proposition в одному реченні + CTA «Почати безкоштовно»
2. **Sign up** — Google / Apple / номер телефону (мінімум полів)
3. **Крок 1/3: Твоя група** — вибір групи ЄП (1/2/3) з human-friendly поясненням, а не юридичним текстом
4. **Крок 2/3: ІПН і дата реєстрації** — з авто-підтягненням даних і підказкою «Де знайти ІПН»
5. **Крок 3/3: Підключи банк** — великі плитки Monobank / Приват24 / Ощадбанк / ПУМБ, з кроком «Або зробити пізніше»
6. **Success screen** — анімація, перші транзакції вже підтягуються, «Ти вже готовий»

**UX-вимоги онбордингу:**
- Progress bar зверху
- Кожен крок — один вибір, без перевантаження
- Skip-посилання для кожного кроку (але з м'яким нагадуванням)
- Мобайл-first (80%+ юзерів зайдуть з телефону)

---

### Блок 3: Головний дашборд

Це — серце продукту. Користувач відкриває застосунок і одразу бачить відповідь на питання: «Скільки мені треба заплатити і коли?»

**Структура дашборду:**

**Hero-секція (top cards):**
- 💰 «До сплати цього кварталу» — сума ЄП + ЄСВ + ВЗ з розбивкою
- 📅 «Наступний дедлайн» — N днів залишилось, назва платежу, сума
- 📈 «Дохід цього кварталу» — гривні + валюта окремо

**Середня секція:**
- Графік доходів по місяцях (bar chart, мінімалістичний)
- Статус Книги обліку: «Актуальна» / «3 непідтверджені транзакції»

**Нижня секція:**
- Останні транзакції (5–7 штук) з можливістю розгорнути
- Банери-нагадування (за 7/3/1 день до дедлайну)

**UX-деталі:**
- Всі числа — з форматуванням (1 200 000 грн, не 1200000)
- Валюта показується поруч: «$3,200 → ₴132,480 (НБУ 41.40)»
- Пустий стан (нема транзакцій) — не порожня сторінка, а CTA «Підключи банк»
- Skeleton loading для кожної картки

---

### Блок 4: Транзакції та Книга обліку

**Список транзакцій:**
- Фільтри: дата (range picker), статус (дохід / повернення / некласифіковано), джерело (банк / Wise / Payoneer)
- Пошук по опису або сумі
- Кожна транзакція: іконка банку, дата, опис, сума (+ валюта якщо є), статус-badge, кнопка «Деталі»
- Bulk selection + «Позначити як дохід» / «Позначити як переказ»

**Деталі транзакції (modal або side panel):**
- Повний опис з банку
- AI-пояснення класифікації («Схоже на оплату від клієнта — позначено як дохід»)
- Поле «Клієнт» (з автодоповненням)
- Поле «Коментар»
- Для валютних: курс НБУ на дату, гривневий еквівалент
- Кнопки: «Дохід» / «Не дохід» / «Переказ між рахунками»

**Книга обліку доходів:**
- Таблиця в форматі Мінфіну (Наказ №579)
- Колонки: № / Дата / Опис / Дохід грн / Дохід валюта / Курс НБУ / Підстава
- Фільтр по кварталу / року
- Кнопка «Завантажити PDF» і «Завантажити Excel»
- Кнопка «Звірити з банком» (показує потенційні розбіжності)

---

### Блок 5: Звітність і КЕП

**Список звітів:**
- Плитки по кварталах: Q1 2026 / Q2 2026 і т.д.
- Статус кожного: Не подано / Підготовлено / Підписано / Прийнято ДПС / Прострочено
- Color-coded: зелений/жовтий/червоний

**Генерація декларації:**
- Wizard на 3–4 кроки
- Крок 1: «Перевір дані» — суми, які ми порахували автоматично, з можливістю ручного коригування
- Крок 2: «Підпиши КЕП» — вибір: Дія.Підпис / monoКЕП / файловий ключ (.dat) / ID-картка
- Крок 3: «Надіслати до ДПС» — progress bar, потім «Отримано квитанцію ✓»
- Крок 4: «Сплати податки» — кнопки deeplink для Monobank / QR-код для Приват24

**КЕП flow:**
- Дія.Підпис: відкривається deeplink в Дію
- monoКЕП: deeplink в Monobank із запитом на підпис
- Файловий ключ: drag & drop .dat файлу + пароль
- Детальні tooltips і help-блоки — користувач вперше зустрічає КЕП, для нього це страшно

---

### Блок 6: Дедлайни і Календар

**Sticky reminder bar:**
- Завжди видимий вгорі (якщо дедлайн < 14 днів)
- «⚠️ До сплати ЄП залишилось 7 днів — 1 729 грн»

**Календар дедлайнів:**
- Повний список на рік з сумами
- Статус: сплачено ✓ / заплановано / прострочено
- Кожен елемент: назва платежу, сума, дата, кнопка «Оплатити»
- Нагадування: toggle Telegram / Email

---

### Блок 7: Налаштування і профіль

- Дані ФОП (ПІБ, ІПН, КВЕД, група, дата реєстрації)
- Підключені банки і платформи (Monobank, Wise, Payoneer) — з кнопкою відключити
- КЕП: зареєстровані ключі
- Нагадування: канали (Telegram, Email), за скільки днів
- Тариф: поточний план, дата оновлення, кнопка upgrade
- Безпека: зміна пароля, 2FA

### Блок 8: Мобайл (iOS і Android)

**Мобайл — окрема версія, не просто "зменшений desktop":**
- Bottom navigation: Дашборд / Транзакції / Звіти / Профіль
- Swipe actions на транзакціях: свайп вправо — «Дохід», свайп вліво — «Не дохід»
- Bottom sheet для деталей транзакції
- Push-нотифікації для дедлайнів
- Haptic feedback на ключових діях (підпис КЕП, успішна подача)
- Biometric auth (Face ID / Touch ID)

## Дизайн-принципи, яких тримаємось

1. **Мінімалізм без порожнечі** — кожен елемент несе сенс, але екран не перевантажений
2. **Numbers first** — цифри — найважливіше. Вони мають бути великими, чіткими, легко читатись
3. **Довіра через прозорість** — показуємо, звідки взялась кожна цифра. Ніякого «магічного» результату
4. **Ukrainian-first** — всі тексти, підказки, help-блоки — українською, без суржику і канцеляриту
5. **Progressive disclosure** — базовий юзер бачить просто; просунутий може розгорнути деталі
6. **Empty states as onboarding** — порожній стан — це не помилка, це запрошення до дії

# Roadmap Kasyr.ai (MVP -> продукт)

Цей документ описує найближчі кроки розвитку застосунку з фокусом на користь для ФОП і зниження ризиків помилок у податках.

## 1) Мобільний UX (перший пріоритет)

Ціль: щоб onboarding, дашборд, транзакції, дедлайни й звіти на телефоні не “ламались”, не перекривались і були читабельні.

Критерії готовності:
- Нічого не перекриває bottom-nav (чат, тости, модалки).
- Великі числа не переносяться по словах/рядках.
- Таби, фільтри та кнопки вміщуються по ширині або коректно переносяться.
- Стабільні відступи (padding) на екранах 360-430px.

## 2) Точність і прозорість розрахунків (1–2 група)

Ціль: щоб ставка ЄП 1–2 групи була або точною (введеною користувачем), або явно “орієнтовною” (граничною), і це було зрозуміло в UI.

Критерії готовності:
- Ставка задається як ціле значення %, у межах 0–10 або 0–20.
- Якщо ставка не задана, застосунок явно позначає: “орієнтовно (гранична ставка)”.
- Пояснення “де взяти ставку” веде до офіційних джерел (див. `OFFICIAL_SOURCES_UA.md`).

## 3) Порожній стан для нового користувача (0 транзакцій)

Ціль: коли транзакцій немає, UI не має створювати враження “ти винен гроші”.

Критерії готовності:
- Усі суми “до сплати” або приховані, або з дисклеймером “потрібні транзакції”.
- Графіки та списки показують зрозумілі підказки “що зробити далі”.
- Дедлайни минулих періодів не позначаються як прострочені для нових акаунтів.

## 4) Надійний імпорт з банку

Ціль: стабільний синк з дедуплікацією, коректною історією, обробкою лімітів Monobank API.

Критерії готовності:
- Повторний sync не створює дублікати.
- Зрозумілі помилки й ретраї.
- Прогрес/стан синку видно користувачу.

## 5) Експорт/звітність “для бухгалтера”

Ціль: зробити експорт максимально практичним (CSV/XLSX, періоди, колонки, коментарі).

Критерії готовності:
- Експорт по року або кварталу.
- Коректні кодування (UTF-8 BOM для Excel) та колонки.
- Чіткий сценарій: “відкрив -> передав бухгалтеру”.

## 6) Нагадування (Email + Telegram)

Ціль: нагадування мають бути “надійні” і керовані користувачем.

Критерії готовності:
- Вибір каналів і тестове повідомлення.
- Налаштування частоти (7/3/1 днів або інше).
- Логи/моніторинг відправок.

## 7) Безпека та акаунти

Ціль: базова безпека та комфортний доступ.

Критерії готовності:
- Reset password.
- Ліміти/захист на auth endpoints.
- Мінімізація “шуму” в консолі (очікувані 401/403 без спаму).

## 8) Підписки

У бета-період логіка може залишатись у бекенді, але UI може бути прихований.

Критерії готовності:
- Єдиний “перемикач” для показу/приховування UI тарифів.
- Таблиця прав доступу в одному місці.
